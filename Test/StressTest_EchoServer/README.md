# Echo Server Stress Test

## 테스트 목표
- 네트워크 라이브러리의 대량 접속 처리, 패킷 송수신 안정성, TPS 처리량 및 세션 정리 로직 검증

## 테스트 조건
Stress Test는 동일한 기준에서 반복 측정할 수 있도록 테스트 조건을 명확히 정의한다.

### 동시 접속 세션 수
서버가 동시에 유지해야 하는 클라이언트 세션 수를 의미한다.

예시:
- 1,000 sessions
- 3,000 sessions
- 5,000 sessions

세션 수를 단계적으로 증가시키면서 접속 성공 여부, 세션 유지 상태, 패킷 송수신 처리량을 확인한다.

### 세션 증가 방식
클라이언트 세션을 한 번에 모두 접속시키지 않고, 일정 간격으로 점진적으로 증가시킨다.

예시:

- 초당 100개 세션 접속
- 초당 500개 세션 접속
- 목표 세션 수 도달 후 일정 시간 유지

이를 통해 순간 접속 부하와 안정적인 세션 유지 가능 여부를 함께 확인한다.

### 패킷 크기
Echo 테스트에 사용되는 패킷의 크기를 의미한다.

예시:

- 32 bytes
- 128 bytes
- 512 bytes
- 1 KB

패킷 크기에 따라 SendPacket TPS, RecvPacket TPS, CPU 사용률, 네트워크 사용량이 어떻게 변하는지 확인한다.

### 세션당 송신 주기

각 클라이언트 세션이 서버로 패킷을 송신하는 주기를 의미한다.

예시:

- 세션당 초당 1회 송신
- 세션당 초당 5회 송신
- 세션당 초당 10회 송신

송신 주기가 짧을수록 서버가 처리해야 하는 패킷 수가 증가하므로, 패킷 처리 성능과 병목 여부를 확인할 수 있다.

### 테스트 시간

각 테스트 케이스를 유지하는 시간을 의미한다.

예시:

- 1분
- 5분
- 10분
- 30분

짧은 테스트는 순간 처리 성능을 확인하는 데 사용하고, 긴 테스트는 메모리 증가, 세션 누수, 버퍼 누적, 장시간 안정성 확인에 사용한다.

### 서버 / 클라이언트 실행 위치

서버와 Stress Test 클라이언트를 같은 머신에서 실행하는지, 별도 머신에서 실행하는지 명확히 구분한다.

예시:

- 서버와 클라이언트를 동일 머신에서 실행
- 서버와 클라이언트를 별도 머신에서 실행
- 동일 네트워크 대역에서 테스트
- 외부 네트워크를 통한 테스트

동일 머신에서 실행할 경우 CPU, 메모리, 네트워크 자원을 서버와 클라이언트가 함께 사용하므로 결과 해석 시 주의가 필요하다.

### 측정 항목

테스트 중 아래 항목을 함께 측정한다.

- 현재 접속 세션 수
- Connect Fail 수
- Disconnect from Server 수
- SendPacket TPS
- RecvPacket TPS
- Echo 응답 지연 시간
- CPU 사용률
- Memory 사용량
- Network 사용량
